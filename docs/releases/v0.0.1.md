# v0.0.12 research preview

Python package version: **0.0.1**. The release tag follows checkpoint **012**. Source and package assets are on [GitHub](https://github.com/krushiraj/OSSoMeX/releases/tag/v0.0.12); model weights are on [Hugging Face](https://huggingface.co/krushiraj/OSSoMeX).

## Included

- Installation, inference, architecture, training and contributor documentation.
- Model cards and manifest-pinned identities for 006 and 012.
- Aggregate three-model benchmarks and known model limitations.
- Reusable training/comparison code, model packaging and synthetic examples.
- An interactive terminal demonstration and a manual Linux CI workflow.

Git does not contain model weights or training/evaluation corpora. Download the complete model bundle separately and preserve its directory layout. No retraining or model promotion is included in this release.

## Installation and compatibility

Use the [quick start](../../README.md) and [model installation guide](../models/README.md). Python 3.11 is the reference environment. CPU inference is supported; compatible Macs can use MPS. CUDA is not exposed by the CLI.

The previously recorded local suite passed 1,869 tests. The [Linux compatibility run](https://github.com/krushiraj/OSSoMeX/actions/runs/37195749223) passed 1,862 tests with seven retained-data skips. CPU inference from an installed wheel succeeded for 006 and 012 on the development Mac. These checks preceded the documentation cleanup and are not a new test run or an independent-machine model evaluation. The [validation receipt](v0.0.12-validation.json) retains their original run identities.

## Source archive refresh

The GitHub source tag and source/package assets are refreshed to exclude internal planning and development records. Source checksums and commit identities therefore differ from the original publication. Model weights, model manifests and the Hugging Face model tag are unchanged. Use the release's current `GITHUB-SHA256SUMS` when downloading the source/package assets.

## Limitations

Both checkpoints are experimental. Attribute quality, cross-domain evaluation, version boundaries and dense-input latency need improvement. See the [benchmark](../research/benchmark-012.md), [model cards](../models/README.md) and [roadmap](../../ROADMAP.md). Source-code Apache-2.0 terms do not automatically determine checkpoint or dataset redistribution terms.
