# OSSoMeX 012 model card

**Experimental. Not promoted as universally better than 006.** Package release: 0.0.1.

## Intended use

Software-name/version candidate extraction from exact research text, followed by local linking, intent, sentiment and alias proposals. Human review is required. Not repository resolution, authorship attribution, or proof of software use from a bare mention.

## Training and identity

The detector uses 011 weights with `wordpiece-bio-v1` decoding and no boundary repair. It was initialized from base SciBERT, not from 006. The input pool contains 900 source records, 2,869 name annotations, 906 version annotations and 1,045 case-folded/whitespace-normalized name strings (1,117 exact spellings). Strings are not resolved projects. The 814 DOI groups include an empty-DOI group; there are 813 nonempty distinct DOIs and 87 records without a DOI.

The other four stages come from the earlier pipeline: linker-004, intent-003, sentiment-003, alias-003. Registry hashes are in `models/registry.json`.

## Evidence and limitations

[Fresh benchmark](../research/benchmark-012.md): 012 leads three local exact-name F1 point estimates and selected recall/version-linking comparisons. Both Softcite engines lead recovered gold. Provisional/exposed snippets cannot establish generalization.

[Known regression](../research/detector-regression.md): 012 misses all names in a MATLAB/Java/TRNSYS passage that 006 partly recovers. Both recognize those names in a simpler context. Greedy decoding does not fix the original failure.

Training includes contradictory empty-label copies of positive text (926 sampled draws out of 7,840). This is a candidate recall defect, not a proven explanation for every miss. Final-epoch selection did not use development-set model selection. Sentiment, aliases, rare intents, version boundaries and dense-window latency need improvement. Scores are uncalibrated.
