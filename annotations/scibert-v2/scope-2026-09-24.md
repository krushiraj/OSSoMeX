# Software scope clarification

Decision ID: software-scope-2026-09-24. User-confirmed on 2026-09-24.
Applies alongside the frozen scibert-poc-2.0 policy, not instead of it.

Annotate named tools, libraries and modules. Do not annotate individual function,
method or class names. Keep programming-language/interpreter mentions within the
existing software scope. Preserve module names as written, including dotted names.

For the real sentence containing Python, numpy, Model, curve_fit, lmfit and
scipy.optimize: label Python, numpy, lmfit and scipy.optimize. Model and curve_fit
are API symbols, not software occurrences under this boundary. This resolution is
a policy decision, not a human acceptance of any particular passage or occurrence.

The task identity and base policy hash in ecosystems-pilot-002 remain immutable.
Its replies record this addendum's decision ID and SHA-256 in annotator provenance.
Retain both files with exports. Apply the same boundary in subsequent calibration,
annotation and evaluation batches. An older corpus with API-symbol labels requires
an explicit compatibility audit; do not silently reinterpret its reference labels.

This decision does not resolve whether a software-name substring in a URL counts
as a separate occurrence. The pilot keeps that exact URL region unresolved and
masked pending review. No algorithm, protein, metric or enzyme identifier becomes
software merely because it resembles a program name.
